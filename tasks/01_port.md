# Задание 1. Перенос на PyTorch с оракулами

**Что тренируем:** приём «оракулов» из доклада (кейс WRF): агент переписывает код,
а тесты автоматически сверяют его с эталоном.

## Шаги
1. Запусти `python oracles/make_oracles.py`, затем `pytest -q`.
   Тесты из `test_reference.py` зелёные, из `test_port.py` красные. Так и должно быть.
2. Сделай коммит: `git add -A && git commit -m "start"`.
3. Дай агенту задачу (можно этим текстом):

   > Прочитай CLAUDE.md и tasks/01_port.md. Перенеси функции из reference/l96_numpy.py
   > в port/l96_torch.py по одной, после каждой запускай pytest. Сначала покажи план.

4. Пока агент работает, не просто жди. Смотри `git diff`: понятно ли, что он меняет?
5. Когда всё зелёное, сделай коммит.

## Вопросы для себя (ответь без агента)
- Почему в PyTorch вместо `np.roll` тоже можно взять `torch.roll`, но с `dims=-1`?
- Зачем тест `test_batched`? Что было бы, если бы функции работали только с одним состоянием?
- Зачем `test_differentiable`? (Подсказка: Задание 3.)

## Мини-эксперимент
Попроси агента ускорить модель (например, прогонять сразу 1000 начальных состояний батчем)
и замерить время по сравнению с эталоном на NumPy в цикле. Тесты при этом должны остаться зелёными.
Это уменьшенная копия результата «быстрее в 14 раз» из доклада.
