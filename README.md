# Стартовый проект: агент + оракулы + гибридная модель (Lorenz-96)

Учебная миниатюра методов из доклада Д. Сухорукова «Терминальные агенты в задачах
автоматизации доменных исследований»:
- **оракулы**: перенос численной модели на PyTorch с автоматической сверкой с эталоном (как WRF → PyTorch);
- **гибридная модель**: нейросеть исправляет ошибку огрублённой физической модели (как NeuralGCM);
- **автоматизация экспериментов**: агент перебирает гипотезы, метрика проверяется автоматически.

Lorenz-96 — игрушечная «атмосфера» из 8 крупных и 256 мелких переменных.
Она считается за секунды на ноутбуке, но устроена так же, как настоящая задача:
крупная модель не видит мелкие процессы, и их влияние надо как-то описать.

## Установка
```bash
python -m venv .venv && source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt
git init && git add -A && git commit -m "init"
python oracles/make_oracles.py
pytest -q        # test_reference — зелёные, test_port — красные (это задание)
```

## Задания (по порядку)
1. `tasks/01_port.md` — перенос на PyTorch с оракулами
2. `tasks/02_coarse_model.md` — огрублённая модель и полиномиальная поправка
3. `tasks/03_nn_correction.md` — нейросетевая поправка
4. `tasks/04_automate.md` — автоматический перебор экспериментов («вширь» и «вглубь»)

## Как работать с агентом
- Запусти агента в папке проекта (например, `claude`). Он сам прочитает `CLAUDE.md` с правилами.
- Делай `git commit` перед каждым заданием. Если агент всё сломал: `git restore .`
- Смотри `git diff`, а не только сообщение агента.
- Если агент «чинит» тесты вместо кода — останавливай. Это запрещено в `CLAUDE.md`.

### Эксперименты из YAML

Обычное обучение поправки по coupling:

```sh
.venv/bin/python -m hybrid.experiment hybrid/configs/supervised.yaml
```

Дообучение через физическую модель:

```sh
.venv/bin/python -m hybrid.experiment hybrid/configs/rollout.yaml
```

В конфиге `hidden_sizes: [32, 32]` задаёт сеть 1→32→32→1, `lr` — шаг
оптимизатора, `epochs` — число эпох, `batch_size` — размер батча.
В rollout-конфиге `horizon: 100` означает прогноз на 100 шагов при обучении,
а `stride` — расстояние между началами обучающих окон. Это не длина итогового
прогноза для графика. Активация Tanh, Adam и float64 остаются фиксированными.

Для нового варианта скопируйте YAML и измените параметры, а также `checkpoint`
и `metrics`, чтобы результаты сохранялись отдельно. Пути внутри YAML отсчитываются
от корня проекта; путь самого YAML — от текущего каталога. Полный конфиг сохраняется
в JSON с метриками.

Rollout использует веса из `initialization`; их архитектура должна совпадать с
`hidden_sizes`. Для новой архитектуры сначала обучите supervised-вариант, затем
укажите его checkpoint в rollout-конфиге. Данные должны уже существовать в `data`.
Старые команды `python -m hybrid.train_neural` и `python -m hybrid.train_rollout`
теперь используют соответствующие YAML по умолчанию.

### Быстрый поиск пяти идей

```sh
MPLCONFIGDIR=/tmp/l96-mpl .venv/bin/python -m hybrid.breadth
```

Скрипт обучает быстрый контроль и проверяет ширину, глубину, SiLU, соседние X
на входе и дообучение через RK4. Снимки параметров каждого запуска сохраняются
в `hybrid/configs/breadth/`, веса, метрики и график — в `results/breadth/`;
сводка дописывается в `results/log.md`. Этот поиск задаётся в `hybrid/breadth.py`;
его YAML — снимки параметров, а не входы команды `hybrid.experiment`.
Сравнение использует 20 одинаковых состояний с seed=45 и средний RMSE до t=1.
Это предварительный поиск на одном seed, а не окончательная оценка качества.

### Поиск вглубь: не больше 10 запусков

```sh
MPLCONFIGDIR=/tmp/l96-mpl .venv/bin/python -m hybrid.depth
```

Нужны результаты `hybrid.breadth`. Выполняются восемь сочетаний горизонта
обучения (50, 100, 200, 400) и lr (0.0001, 0.001), затем два повтора лучшего
сочетания. Каждый запуск — 10 эпох дообучения быстрого контроля. Выбор по
среднему RMSE до t=1 на seed=45; итоговая проверка выбранного варианта и его
повторов — на новых состояниях seed=46. Финальный ансамбль не используется
для выбора весов. Сохраняются конфиги `hybrid/configs/depth/`, результаты
`results/depth/` и запись в `results/log.md`. Отдельный запуск воспроизводится
командой `python -m hybrid.experiment hybrid/configs/depth/run_01.yaml`.
